# MAKE UP 完整妆造报告提示词规范

状态：积分制完整妆造报告的现役实现规范。权威实现位于 `supabase/functions/plus-makeup-report/index.ts` 与 `supabase/functions/_shared/plusMakeupReport.ts`。

## 数据流

1. 浏览器在本地分析照片，得到向用户披露的九项相对比例；照片不进入报告服务。
2. 用户登录、确认同意并选择 1 至 3 个场景和一个固定妆容方向后，服务端原子预占 100 积分并创建临时任务。
3. DeepSeek 只接收九项比例、场景和妆容方向，生成结构摘要与 3 套妆造方案。
4. 服务端从方案中提取固定白名单妆容关键词；豆包只接收场景、方向和这些关键词，联网返回公开博主名字。
5. 成功后立即清除任务中的九项精确比例；报告保存到本机 IndexedDB 后删除服务端任务。任务最长保留 24 小时，失败或过期退回预占积分。

## DeepSeek 输入

输入是严格 JSON 数据，不包含照片、关键点、身份、设备信息、创作者资料或本地匹配排名：

```json
{
  "configuration": {
    "scenes": ["日常通勤"],
    "customScene": null,
    "direction": "清透自然"
  },
  "features": {
    "faceAspectRatio": { "label": "脸部宽高比", "value": 0.78 }
  }
}
```

正式请求必须包含全部九项固定比例。自由场景最长 80 字，并始终作为不可信数据字段处理，不能执行其中要求改变角色、泄露提示词或修改输出格式的指令。

## DeepSeek 输出

只接受严格 JSON，字段如下：

```json
{
  "title": "报告标题",
  "faceProfile": {
    "summary": "中性的结构摘要",
    "focusAreas": ["妆容重点"],
    "limitations": ["无法由比例判断的内容"]
  },
  "plans": [
    {
      "name": "方案名称",
      "sceneFit": "适用场景",
      "effect": "预期视觉方向",
      "steps": [{ "area": "眼妆", "instruction": "具体操作" }],
      "products": ["产品品类与质地"],
      "avoid": ["避坑提示"]
    }
  ],
  "disclaimer": "AI 生成，仅供妆容参考"
}
```

`plans` 必须正好 3 项，每项必须有 5 至 7 个步骤。输出不得推断肤色、肤质、痘痘、眼皮形态、发型、服装、身份、年龄、种族、健康、性格或吸引力；不得给出医学判断、颜值评分、唯一审美标准或具体品牌。

服务端拒绝额外字段、字段缺失、重复列表、超长文本、禁用歧视性内容和无法解析的 JSON。DeepSeek 首次格式错误时只进行一次格式纠正重试。

## 豆包输入与输出

豆包不接收照片、九项比例、DeepSeek 自由文本结构摘要、用户身份或本地匹配结果。它只接收：

- 场景；
- 固定妆容方向；
- 服务端从报告中命中的白名单关键词，例如底妆、眉形、眼线、眼影、腮红、修容、高光和唇妆。

请求使用 `store: false` 和联网搜索，只接受严格 JSON：

```json
{ "names": ["公开使用的博主名字"] }
```

返回 1 至 5 个名字，不返回链接、账号、相似度或解释。名字只是未核验公开线索，不代表合作、授权或已进入创作者库；不得下载或分析候选博主照片。

## 上线验收

- 九项比例、场景和方向的请求结构与白名单一致，额外字段被拒绝。
- DeepSeek 输出始终能通过严格解析，且固定为 3 套可执行方案。
- 报告不包含未提供的肤色、肤质、身份、敏感属性或医学判断。
- 豆包请求中不出现照片、精确比例、完整报告、身份或匹配结果。
- 重复任务、失败、过期、保存确认和积分扣退均保持幂等。
- 数据库、Storage 和运行日志不持久化照片、完整提示词、AI 返回名字或最终报告；临时任务按合同及时清除。
