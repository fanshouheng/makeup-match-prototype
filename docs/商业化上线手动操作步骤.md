# MAKE UP 商业化上线手动操作步骤

更新日期：2026-09-16

本文只列出必须由项目所有者完成或确认的操作。正式目录为单次报告、月卡和年卡；对应价格为 ¥19.9 / ¥59 / ¥599 与 US$2.99 / US$8.99 / US$89.99。代码检查、数据库迁移、Edge Function 部署和上线验证由 Codex 完成。这里的检查只用于支付安全，不再测试价格或套餐。

## 操作原则

- 不把任何密钥、银行卡资料或支付回调内容发送到聊天、Git、日志或截图中。
- 不执行 `supabase migration repair`。旧迁移记录分叉仍需整理；本次统一积分迁移已通过远端原始历史隔离目录精确推送。
- 不先打开生产环境的 `VITE_ENABLE_ONLINE_CHECKOUT`。测试订单使用 Codex 准备的临时测试入口，生产页面继续关闭支付。
- Stripe 先用测试模式；ZPAY 没有可用沙盒时，只做一笔可控的小额真实订单并人工盯单。
- 整个支付验收不需要 Docker。

## 第 1 步：配置 ZPAY

商务号、微信支付方式和回调地址已配置。商户密钥由项目所有者直接写入 Supabase，未经过聊天或项目文件。金额、币种和积分不使用 Secrets，而由受保护的 `membership_plans` 目录决定。

配置方式如下，后续轮换密钥时仍按此操作：

1. 在 ZPAY 商户后台找到“API 信息”或商户密钥，不要把密钥发到聊天。
2. 打开 Supabase Dashboard 的 Edge Functions -> Secrets，新增或更新：

   ```text
   ZPAY_KEY=商户密钥
   ```

3. 保存后只回复“ZPAY_KEY 已配置”，不要提供具体值。

已核验存在的项目如下，无需重复填写：

```text
   ZPAY_PID=<已配置>
   ZPAY_NOTIFY_URL=https://srydzphmmepcywepcccq.supabase.co/functions/v1/payment-webhook
   ZPAY_RETURN_URL=https://makeup.soul.xn--fiqs8s/report
   ZPAY_TYPE=wxpay
```

旧 `PAYMENT_PLUS_*` 和 `PAYMENT_AI_CREDITS_*` 即使仍存在也不参与新积分订单，不要再修改它们来测试价格。

## 第 2 步：配置 Stripe 测试模式

在 Stripe Dashboard 中完成，不把值发到聊天：

1. 切换到测试模式并取得 `sk_test_...` Secret key。
2. 新建 webhook endpoint：

   ```text
   https://srydzphmmepcywepcccq.supabase.co/functions/v1/payment-webhook
   ```

3. 订阅以下事件：
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.paid`
   - `invoice.payment_failed`
   - `invoice.payment_action_required`
   - `charge.refunded`
   - `refund.updated`
4. 取得该 endpoint 的 `whsec_...` signing secret。
5. 在 Supabase Dashboard 的 Edge Functions -> Secrets 中填写：

   ```text
   STRIPE_SECRET_KEY=sk_test_...
   STRIPE_WEBHOOK_SECRET=whsec_...
   ```

6. 只回复“Stripe 测试 Secrets 已配置”，不要提供具体值。

## 第 3 步：Stripe 测试订单

1. Stripe 测试 Secrets 配置完成后，由 Codex 启动临时测试入口并核对准确地址；不要在仍显示旧 Plus 的生产页测试。
2. 使用测试账号登录该入口，在 `/report` 的会员区域选择唯一的 MAKE UP Pro 和 Stripe。
3. 使用 Stripe 官方测试卡 `4242 4242 4242 4242`；有效期填未来日期，CVC 填任意三位测试值。
4. 支付返回后告诉 Codex“Stripe 测试订单已完成”。
5. Codex 核对订单 `pending -> paid`、积分到账、重复 webhook 和全额退款回滚。

## 第 4 步：ZPAY 小额盯单

1. 由 Codex 继续使用同一个临时测试入口；生产支付仍保持关闭。
2. 先确认 ZPAY 是否提供沙盒或测试通道。
3. 有沙盒时使用沙盒；没有时分别按正式单次报告、月卡和年卡完成小范围真实订单验收，随后按退款流程处理。不要临时修改套餐金额。
4. 支付过程中保持 Codex 在线核对订单状态、权益发放和异步通知。
5. 完成管理员全额退款，确认 ZPAY 后台、MAKE UP 订单和权益只回滚一次。

## 第 5 步：发布前端并开启支付

只有 Stripe 和 ZPAY 验收均通过后：

1. 在 Vercel 生产环境变量中设置：

   ```text
   VITE_ENABLE_ONLINE_CHECKOUT=true
   ```

2. 授权 Codex 发布当前 `main` 到生产。
3. Codex 验证桌面和移动端 `/report`、`/plus` 兼容跳转、支付回跳、管理台聚合、错误状态和隐私边界。

## 第 6 步：首笔真实订单

1. 选择一笔可控小额真实订单并人工盯单。
2. 核对到账、订单状态、积分余额、报告生成和退款联系人。
3. 确认无重复发放、无敏感信息日志、无未处理退款后，商业化上线才算完成。
